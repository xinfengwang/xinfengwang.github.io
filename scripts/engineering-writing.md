# Agent Engineering 文章规范

每篇文章回答一个读者真正会遇到的问题。用一条具体输入、一次失败或一个设计取舍开场，先讲清楚为什么需要这项技术，再沿同一个例子解释它怎样工作。

## 正文怎么展开

- 介绍概念时先给定义，再用一个读者能跟得上的例子说明。标明前置知识和容易混淆的概念。
- 展开机制时具体到一次计算、一次状态转移或一条消息。说明谁产生输入、谁持有状态、何时更新、失败在哪一层被识别，以及最后怎样验收。
- 用 Mermaid 画清楚关系复杂的部分，例如回执如何回到模型、证据何时进入上下文、恢复如何读取检查点。图后解释关键分支，公式的符号和假设应在正文定义。
- 用同一业务输入比较不同方案。说明实现细节怎样改变质量、延迟、成本和故障处理。表格用于总结，关键判断写进正文。
- 说明技术在 Agent 中的职责和适用边界。概览读完能画出全流程，深读能解释其中一个机制，案例能沿输入、中间证据和交付物验证设计。
- 代码、伪代码、公式、时序图和表格按讲解需要选用。已有可运行示例可作选读。只有以实验为主题的文章需要交代环境、输入和预期结果；不要把运行日志、依赖文件或完成断言当作理论文章的必备段落。
- 涉及框架、协议和模型接口的时效性行为，链接官方规范或文档，并标出限制成立的版本或条件。性能、成本与效果结论注明样本和设定，合成示例与实测结果明确标注。

结构随主题调整。Agent Loop 适合跟一次任务逐轮展开，Transformer 适合从 Q、K、V 推到下一 token，LangGraph 的恢复适合对比中断前后的状态快照。

## 本章重点问题

在文章 front matter 的 `chapter_questions` 写 `question` 和 `answer`。布局会在正文总结后、阅读路线和相关文章前渲染该章，目录随之出现。答案使用 Markdown，默认折叠。概览通常五题，机制较复杂时可到八至十题。

至少覆盖三种理解方式。基础题辨认概念及其边界，原理题推演一个关键步骤，综合题把同一机制应用到失败定位或方案选型。答案给出判断依据和条件，必要时分段或使用短列表。整章问答紧贴本篇正文，答案中优先用段落、列表和短公式。

## 入库与验收

- 在 `_posts/` 按[文章模板](templates/engineering-article.md)写作。`engineering_topic` 使用 `_data/agent_engineering.yml` 的板块 ID，必要时将文章 slug 登记为 `chapters`。
- `outline` 要引用文章中真实的 H2 锚点。已用于分享和站内跳转的文章路由、手写锚点继续有效。
- 在 `engineering_reading` 维护前置、后续和相关专题。正文有明确关联时就地链接。`continue_reading` 指向最适合下一步的文章。
- 按[知识覆盖清单](engineering-content-map.md)更新专题状态和章节问答情况。重复定义由概览负责，细节由专题负责，案例只保留解读当前业务所需的背景。
- 运行 `python scripts/build_connections.py` 更新关联数据，构建 Jekyll 后检查正文、目录定位、Mermaid、链接和阅读时间。在桌面与窄屏检查问答默认折叠，鼠标或键盘能展开、收起，八个入口及既有文章正常打开。
