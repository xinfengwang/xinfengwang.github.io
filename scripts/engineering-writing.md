# Agent Engineering 深度文章规范

先读专题页、已有正文和文章之间的链接。从一次有输入、有失败现象、有可验收交付的工程问题出发。每篇只解决一个主要问题。同一个技术可用多篇逐层展开，前一篇交付的概念应能在下一篇直接复用。

| 正文章节 | 读者最终能回答什么 | 检查方式 |
| --- | --- | --- |
| 背景与问题 | 什么时候会遇到这个问题？传统实现卡在哪里？ | 给出同一个请求的成功与失败路径 |
| 核心概念 | 关键对象是什么，分别由谁拥有？ | 说明输入、输出、权限与生命周期 |
| 底层原理 | 一次决策或状态转移由什么触发？ | 使用数据结构、伪公式或算法解释机制 |
| 系统架构 | 哪些组件参与？数据和控制权怎么流动？ | Mermaid 图只表达一层关系，图下补充边界 |
| 完整执行流程 | 正常与异常执行分别怎么走？ | 用时序图与一次可核对的执行记录 |
| 核心代码 | 如何复现？中间状态和结果怎样验证？ | 优先 Python，提供命令、版本、输入、输出与断言 |
| 方案对比 | 什么条件会改变选型？ | 固定同一任务、证据与预算进行对照 |
| 工程实践 | 怎样检测失败、恢复、优化和保留证据？ | 明确超时、预算、幂等、权限或评测的适用边界 |
| 总结与延伸 | 前后专题怎样衔接？ | 明确前置知识、后续阅读和相关专题 |

## 在仓库里开始一篇

- 复制 [文章模板](templates/engineering-article.md) 到 `_posts/`。目录字段 `outline` 的每项需要对应正文真实的 H2 锚点。标题允许调整，已有被引用的锚点需保留。
- `engineering_topic` 使用 `_data/agent_engineering.yml` 里的现有板块 ID。必要时把文章 slug 注册为该板块的 `chapters`。修改已有文章时沿用日期与 slug。
- 用 `engineering_reading` 配前置、后续和相关链接。正文里保留真正支持论述的链接，便于生成可解释的双向关联。程序只从正文提取反向引用。
- Mermaid 使用代码围栏，架构图和时序图各自聚焦一个问题。Python 代码放在 `assets/examples/` 的专题目录。正文摘录应与可下载版本一致，命令从读者下载后的目录起步。
- 合成数据与确定性模型替身须注明。数字应来自实际运行，或清楚标明是用来解释算法的构造例。引用框架行为时查官方版本文档，记录实际测试版本。密钥、真实用户数据和线上副作用不进入可运行示例。
- 提交前运行示例和 `python scripts/build_connections.py`，构建 Jekyll。检查九节的锚点、右栏、移动端目录、流程图、代码、相关阅读及既有页面。

## 分阶段建设

先以基础篇作为标准。之后按核心技术、架构、框架、生产工程、项目实战的顺序深化现有文章。每次迭代重新检查专题的已覆盖与未覆盖问题，避免用重复文章填目录。评估、安全和可观测性作为每个工程案例的验收线，在原有板块保留专题入口。
