Agent 开发知识地图

从一份能验收的需求开始，做出能调用工具、处理异常、稳定交付的 Agent。按开发流程走一遍，也可以从当前遇到的问题进入专题。

Agent 全生命周期开发流程

线上失败进入回归集，再回到需求、架构或能力实现。交付目标变了，就重新定义验收条件。

flowchart TB
      A["需求分析与场景定义"] --> B["Agent 架构设计"]
      B --> C["核心能力开发"]
      C --> D["编排与协作"]
      D --> E["评估与安全治理"]
      E --> F["部署与生产运维"]
      F --> G["持续优化与迭代"]
      G -->|按失败原因修订| A
  1. 需求分析与场景定义确认用户、输入、交付物、权限边界和成功标准，写出正常、缺信息及越界用例。
  2. Agent 架构设计确定谁决定下一步，任务状态存在哪里，工具、模型和记忆怎么分工。
  3. 核心能力开发做出模型调用、工具、检索、记忆和规划的最小链路，并保留可核对的中间结果。
  4. Agent 编排与协作串接状态迁移、角色交接和人工审批，验证中断后能否按预期恢复。
  5. 评估与安全治理用固定任务做回归，在工具执行前检查权限，用 Trace 定位失败环节。
  6. 部署与生产运维上线服务和 Worker，配置超时、监控、灰度与回滚，并量化延迟和成本。
  7. 持续优化与迭代收集真实失败，重放并找出最早的偏差。修复进入下一轮回归和发布。

Agent Engineering 学习路线

第一次接触 Agent，可以从模型调用读到生产系统。想解决眼前的问题，可以直接进入对应阶段。

  1. 认识 Agent从 LLM 到 Agent，再跟着运行循环理解动作、状态和验收。
  2. 掌握核心能力先读 LLM 与 Prompt、Function Calling 和 RAG，再串联记忆、规划与推理。
  3. 设计系统架构从固定工作流出发，比较 ReAct、计划执行和多 Agent 的决策边界。
  4. 选择框架和协议沿同一条执行链看 LangGraph 的状态与恢复，再看 MCP 与 A2A 的职责。
  5. 从 Demo 走到生产理解写入恢复、并发、部署和回滚，再读评估、安全与可观测性。
  6. 用案例检验设计从智能客服进入资料研究、多 Agent 开发和企业平台，之后继续读长时运行等前沿方向。
